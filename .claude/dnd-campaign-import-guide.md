# D&D 战役模组 PDF 导入指南

> 本指南用于将 D&D 5e 战役模组 PDF（中文/英文，200-500 页）转换为结构化 markdown 文件，供 `trpg-battle` 项目的 AI DM 使用。

---

## 1. 输出结构

每个模组输出到 `output/Dnd5e/campaign/world/{module-name}/` 目录下，包含以下文件：

| 文件 | 用途 | 必须 |
|------|------|------|
| `region.md` | 区域总览：背景、地点表、旅行时间、主线流程 | 是 |
| `quests.md` | 任务钩子：每个任务的看板原文、委托人、目标、奖励、XP、攻略要点 | 是 |
| `npcs.md` | NPC 索引：按地点分组，含种族/身份、位置、态度、关键信息 | 是 |
| `encounters.md` | 遭遇表：各地点固定遭遇 + 随机遭遇表 + 增强版适配 + XP 速查 | 是 |
| `shops.md` | 商店与交易：商店列表、魔法物品索引、各地点可回收财宝汇总 | 是 |
| `{location-name}.md` | 地点详情：每个可探索地点一个文件，含逐区域描述 | 是 |

---

## 2. 文件格式规范

### 2.1 通用规范

- GitHub Flavored Markdown
- 中文为主，专有名词格式：`中文名（English Name）`——与 PDF 原文一致
- 数值必须精确：AC、HP、DC、伤害骰、距离、持续时间等不可有误
- 交叉引用格式：`详见 filename.md` 或 `详见 filename.md 区域 X1`
- 区域编号用单字母前缀 + 数字：`G1`、`E11`、`B10`——字母取自地点英文名首字母

### 2.2 `region.md` — 区域总览

```markdown
# 模组名（English Module Name）

## 冒险背景
（1-3 段概述：谁、在哪、发生了什么、为什么冒险者要介入）

---

## 主要地点

### 分区名（如：城镇周边 / 森林深处 / 山脉）

| 地点 | 方位 | 距离 | 等级 | 概述 |
|------|------|------|------|------|
| **地点中文名（English Name）** | 方位 | X 英里 | LX | 一句话概述。详见 `filename.md` |

---

## 距离与旅行时间

| 路线 | 徒步 | 备注 |
|------|------|------|
| A → B | X 天 | 路况说明 |

---

## 旅行规则
（行军速度、导航检定、遭遇检定频率等）

---

## 区域地点详情索引
- 地点名（X 个区域）→ 详见 `filename.md`

---

## 主线流程概览
（用文字或 ASCII 流程图展示任务解锁条件和依赖关系）
```

### 2.3 `quests.md` — 任务钩子

```markdown
# 模组名 — 任务钩子汇总

---

## 任务系统说明
（任务来源、解锁机制、奖赏发放方式等）

---

## 第 X 阶段任务

### 任务编号：地点名（English Name Quest）

- **看板原文 / 任务触发**："引号内原文"
- **委托人**：NPC 名（任务来源）
- **目标**：完成条件
- **奖励**：
  - 金币：X gp
  - 物品：魔法物品名
  - 战斗 XP：怪物名 CR X = Y XP
- **关联地点**：`filename.md`（区域编号范围）
- **攻略要点**：关键信息、可选路线、陷阱提示

---

## XP 速查（按地点）

| 地点 | 主要 XP 来源 | 预估战斗 XP | 备注 |
|------|-------------|------------|------|
```

### 2.4 `npcs.md` — NPC 索引

```markdown
# 模组名 — NPC 索引

---

## 地点名（English Name）

### NPC 中文名（English Name）
- **种族/身份**：种族 + 性别 + 职业/身份
- **位置**：地点名 区域 X1
- **态度**：2-3 个描述词
- **关键信息**：角色在故事中的作用、战斗数据块引用、特殊能力、与其他 NPC 的关系
- **详见**：`filename.md` 区域 X1
```

### 2.5 `encounters.md` — 遭遇表

```markdown
# 模组名 — 遭遇表

## 队伍适配指引
（等级缩放建议）

---

## 随机遭遇表（如有）

| dX | 遭遇 |
|----|------|

---

## 各地点固定遭遇索引

### 地点名（English Name）

| 区域 | 怪物配置（原版） | 增强版（LX-Y 适配） | 备注 |
|------|-----------------|-------------------|------|
| X1 | Creature ×N | **Creature ×M, HP XX** | 触发条件/行为 |

> 详见 `filename.md`

---

## XP 速查（按 CR）

| CR | XP | 常见怪物 |
|----|-----|---------|
```

### 2.6 `shops.md` — 商店与交易

```markdown
# 模组名 — 商店与交易

---

## 商店名（地点名）

- **店主**：NPC 名，种族，背景
- **商品**：

| 物品 | 价格 |
|------|------|

- **备注**：开放条件、特殊规则

---

## 魔法物品索引

| 物品 | 地点 | 区域 | 稀有度 | 需同调 | 备注 |
|------|------|------|--------|--------|------|

---

## 各地点可回收财宝汇总

### 地点名

| 来源 | 物品 | 价值 |
|------|------|------|
```

### 2.7 `{location-name}.md` — 地点详情

```markdown
# 地点中文名（English Name）

LX 冒险。一句话定位描述。

## 背景
（2-3 段：这个地点的历史、当前状况、敌人配置）

---

## 任务目标（如有关联任务）
（完成条件、奖励预览）

---

## 抵达
> 朗读文本（boxtext）：角色接近时看到/听到/感受到什么

（抵达方式、入口描述、DC 检定）

---

## 通用特征（Location Features）

- **天花板**：高度
- **门**：材质、开锁 DC、破门 DC、暗门发现 DC
- **光照**：光源类型
- **特殊**：噪音、气味、温度等环境因素

---

## 特殊机制（如有）
（狂野魔法表、环境危害、特殊规则等）

---

## 地点区域

### X1. 区域中文名（English Name）

> 朗读文本（boxtext）：角色进入时的描述

（区域详情：NPC、怪物、宝藏、机关、可交互物品）

- **怪物**：Creature Name ×N（数据块引用）
  - 关键数据：AC X, HP Y, 攻击 +Z, 伤害 XdY
  - 行为/触发条件
- **宝藏**：物品名（价值/效果）
- **DC 检定**：Skill DC X（效果描述）

#### 增强版（LX-Y 适配）
（缩放调整：HP 变化、数量变化、新增遭遇）

---

### X2. 下一个区域...

---

## NPC 名录（如有大量 NPC）

| 区域 | NPC |
|------|-----|

---

## 增强版遭遇汇总（LX-Y 适配）

| 区域 | 原版 | 增强版 |
|------|------|--------|
```

## 3. 导入流程

### 3.1 第一步：读取目录，生成导入计划

1. 读 PDF 前 5-10 页（目录、引言）
2. 列出所有章节和地点
3. 确定输出文件列表（哪些地点需要独立文件）
4. 生成 `{module-name}-import-plan.md`，包含：
   - 每个对话处理哪些页码/章节
   - 预估对话数量
   - 文件写入顺序

### 3.2 第二步：逐章提取

每个对话的工作流：

```
1. 读取本指南（campaign-import-guide.md）+ 导入计划
2. 读取当前输出文件（了解已完成的部分）
3. 读 PDF 对应页码（每次最多 20 页）
4. 提取内容，按格式规范转为 markdown
5. 写入/追加到对应输出文件
6. 执行章节检查清单
7. 监控 context 使用量 → 接近阈值时主动结束（见 §3.5）
8. 继续下一章节（不要停下来问用户）
```

### 3.3 建议的处理顺序

```
对话 1：目录 + 导入计划 + region.md（背景、地点表、旅行、流程）
对话 2-N：逐个地点文件（按模组章节顺序）
倒数第 2 个对话：汇总文件（quests / npcs / encounters / shops）
最后一个对话：交叉校验 + 修正
```

> 汇总文件放在后面做的原因：它们需要引用所有地点的数据，在地点文件全部完成后编写更准确。
> 但如果 PDF 结构是先给总览再给地点详情，也可以先写汇总文件，后续补充。

### 3.5 Context 管理与对话切换

**核心原则**：context 堆积后提取质量会下降。宁可多开几个对话，也不要在长 context 下勉强输出。

**何时结束当前对话**：

- 每个对话处理 **1-2 个地点文件**或 **40-60 页 PDF** 为宜
- 如果感觉 context 已经很长（大量 PDF 内容 + 输出内容堆积），在当前章节/地点完成后立即结束
- **不要在一个区域写到一半时切换**——至少完成当前地点文件再结束

**结束对话时的交接**：

在对话末尾输出一段交接摘要，包含：
1. ✅ 本次完成的文件和章节
2. 📋 下次对话应处理的内容（页码范围 + 对应输出文件）
3. ⚠️ 需要注意的问题（术语不确定、OCR 存疑、交叉引用待补等）

**新对话的启动流程**：

```
1. 读取 campaign-import-guide.md（本文件）
2. 读取 {module-name}-import-plan.md（导入计划）
3. 读取上次对话的交接摘要（如有）
4. 读取已完成的输出文件（检查当前进度）
5. 继续下一个章节
```

> 导入计划中应标记每个章节的完成状态，新对话可以快速定位到未完成的部分。

### 3.6 自动定时导入模式（推荐）

可以用 Claude Code 的 `/schedule` 功能设置 cron 定时任务，每 30 分钟自动启动一轮导入。每轮是独立对话、独立 context，不会膨胀。

**设置方式**：

```
/schedule 创建一个每 30 分钟运行的定时任务：
  进入 /Users/jack/Projects/dnd-rules-import
  读取 campaign-import-guide.md 和当前模组的 import-plan
  按计划继续导入下一个未完成的章节
  完成后更新 import-plan 的进度标记
```

**导入计划的进度跟踪格式**：

在 `{module-name}-import-plan.md` 中用状态标记每个步骤：

```markdown
| 步骤 | 内容 | PDF 页码 | 输出文件 | 状态 |
|------|------|---------|---------|------|
| 1 | 目录 + region.md | 1-15 | region.md | ✅ 完成 |
| 2 | 第一章 地点 A | 16-35 | location-a.md | ✅ 完成 |
| 3 | 第二章 地点 B | 36-55 | location-b.md | 🔄 进行中 |
| 4 | 第三章 地点 C | 56-70 | location-c.md | ⬜ 未开始 |
| ... | ... | ... | ... | ... |
```

**每轮自动任务的执行逻辑**：

```
1. 读取 campaign-import-guide.md
2. 找到当前模组的 import-plan
3. 扫描状态列，找到第一个 ⬜ 或 🔄 的步骤
4. 如果所有步骤都是 ✅ → 执行最终交叉校验，然后标记整个模组完成
5. 否则 → 执行该步骤（读 PDF、写输出文件）
6. 完成后将该步骤状态更新为 ✅
7. 如果 context 允许，继续下一个 ⬜ 步骤（最多处理 2 个地点）
8. 输出交接摘要到 import-plan 文件末尾
```

**优势**：
- 完全无人值守，连续导入直到完成
- 每轮独立 context，不会质量退化
- 进度可追踪，中断后可自动恢复
- 200 页模组约 5-8 小时自动完成（10-15 轮 × 30 分钟间隔）

### 3.4 每章节检查清单

每提取一个章节/地点后，检查：

- [ ] **完整性**：PDF 中该章节的所有小节/区域是否全部包含？
- [ ] **数值准确**：抽查 3-5 个关键数值（AC/HP/DC/伤害骰/距离），与 PDF 原文对比
- [ ] **表格完整**：所有表格的行数是否与原文一致？
- [ ] **格式一致**：标题层级、区域编号、术语格式是否统一？
- [ ] **交叉引用**：区域编号和文件名是否正确？
- [ ] **无乱码**：没有 PDF 提取残留的特殊字符或断行错误

## 4. OCR 扫描 PDF 注意事项

OCR 扫描的 PDF 常见问题及处理方式：

| 常见错误 | 处理方式 |
|----------|---------|
| 数字混淆（1/l/I, 0/O, 5/S） | 根据上下文和 5e 规则常识修正。AC 通常 10-20，HP 通常个位到三位数 |
| 中文断行错误（句子被拆成多行） | 合并为完整句子 |
| 表格列错位 | 根据列头和数据类型重新对齐 |
| 特殊符号丢失（—、×、·） | 补回正确符号 |
| 英文术语拼写错误 | 修正为 5e 标准术语 |
| 页眉/页脚混入正文 | 删除 |
| 图片 alt-text 或说明混入 | 删除，仅保留文字内容 |

**原则**：如果 OCR 结果含义模糊且无法从上下文推断，标注 `[OCR 存疑：原文为"xxx"]` 供后续人工校对。

## 5. 增强版适配规则

现有模组（icespire-peak）的增强版设计原则：

- **目的**：为高于模组设计等级的队伍（如 L4-5 打 L1 模组）提供适当挑战
- **方法**：
  - 提升怪物 HP（通常 +30-50%）
  - 增加怪物数量
  - 提升 DC（通常 +2）
  - 新增遭遇（在原版无战斗的区域添加怪物）
  - 新增精英/变种怪物（如 Ankheg Matriarch）
- **格式**：在每个区域描述后添加 `#### 增强版（LX-Y 适配）` 子段落
- **汇总**：在文件末尾添加 `## 增强版遭遇汇总` 表格

> 增强版是否需要，取决于实际战役中队伍的等级。导入时如果 PDF 无增强版数据，可以跳过；后续根据需要由 DM 手动添加。

## 6. 怪物数据处理

地点文件中的怪物数据**不需要写完整数据块**（完整数据块在 `rules/5e-mm.md` 中）。只需：

1. **引用数据块名称**：`使用 Veteran 数据块` 或 `使用 Orc 数据块`
2. **列出与标准数据块的差异**：如 HP 修改、额外能力、装备变化
3. **自定义怪物**（PDF 中独有的、MM 中没有的）：写完整数据块

```markdown
**石寒掠夺者（Stone-Cold Reavers）×4**：使用 Veteran 数据块
- 阵营：混乱邪恶
- 行为：可能伪装友好后偷袭

**塔洛斯隐修士格兰诺克（Grannoc）**：使用 Anchorite of Talos 数据块（CR 3）
- 身上有地图标注雷鸣之环位置
```

对于 PDF 中独有的自定义怪物（如 Anchorite of Talos、Gorthok），需要在地点文件中写出完整数据块，或集中写在 `encounters.md` 的附录中。

## 7. 跨文件一致性

导入完成后，确保以下一致性：

- [ ] `region.md` 地点表中的所有地点都有对应的 `.md` 文件
- [ ] `quests.md` 中的关联地点链接指向正确文件名
- [ ] `npcs.md` 中的区域编号与地点文件中的编号一致
- [ ] `encounters.md` 中的怪物配置与地点文件中的描述一致
- [ ] `shops.md` 魔法物品索引包含所有地点文件中出现的魔法物品
- [ ] `shops.md` 财宝汇总包含所有地点文件中的可回收财宝
- [ ] NPC 名字在所有文件中拼写一致（中文名 + 英文名）
- [ ] 等级标注一致（region 地点表 vs 地点文件开头 vs quests 中的关联）
- [ ] 区域编号前缀字母在所有文件中一致（如 G = Gnomengarde）
