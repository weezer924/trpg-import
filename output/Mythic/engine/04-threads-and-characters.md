# Threads And Characters Lists

> Two weighted random tables that double as the adventure's memory.

## When To Use

- End-of-Scene Bookkeeping (default editing window).
- Mid-Scene when an element becomes load-bearing and you don't want to wait.
- Whenever a Random Event Focus needs an NPC or Thread (roll on the relevant List).

## Procedure

### Adding

- **Threads** — goals the PC is pursuing. Verb-object phrases ("Capture the fugitive", "Find the book").
- **Characters** — NPCs, organizations, locations, environmental forces, recurring objects (anything that can act for or against the PC).
- At end of Scene, for every prominent Thread/Character in the Scene that's already on a List, **add another instance**. This weights it for future random rolls.
- **Cap: 3 instances per element.** Once an element appears 3 times, no more entries.

### Removing

- Remove resolved/abandoned Threads (or all instances of an irrelevant Character).
- Cross out maxed-out Threads when the underlying goal completes.

### Rolling On A List

Lists hold up to 25 entries in 5 sections of 5 rows each. Active sections = sections with at least one entry.

| Active sections | Section-select die                           |
|-----------------|----------------------------------------------|
| §1 only (≤5)    | no roll, use §1                              |
| §1–§2 (6–10)    | d4 (1–2 → §1, 3–4 → §2)                      |
| §1–§3 (11–15)   | d6                                           |
| §1–§4 (16–20)   | d8                                           |
| §1–§5 (21–25)   | d10                                          |

Then roll **d10** for the row within the selected section: 1–2 → row 1, 3–4 → row 2, 5–6 → row 3, 7–8 → row 4, 9–10 → row 5.

If the rolled line is **blank** → **Choose**: pick an existing element that fits the Context, or reroll until a filled line lands.

### "But They're Not Here"

A rolled NPC need not be physically present. The Event simply *involves* them — by reputation, evidence, news, an item left behind, or a connection to whoever is on-stage.

### List Cleanup

When a List fills up:
- Copy elements you want to keep onto a fresh sheet, with one entry each.
- Elements that previously had 3 entries get 2 on the new sheet (preserving relative weight).
- Optionally consolidate minor NPCs into group entries ("Villagers", "Townsfolk").

## Decision Tree

- "Should I add this NPC?" — Will they / could they meaningfully act again? Add. Just colour? Skip.
- "Add a non-Character to the Characters List?" — Yes when the location/object/event has its own activity that could shape future Scenes (a haunted mansion, a faulty starship, a wandering horde, a "Zombie attack!" event-as-Character).
- "Three Threads is enough — should I add more?" — Sparse Threads = focus; many Threads = sandbox. Decide by what kind of session you want.
- "Do I add or wait until end-of-Scene?" — Add mid-Scene if the element is *already* eligible to be rolled in this Scene's later events; otherwise, save for Bookkeeping.
- "Element on multiple Lists?" — Allowed when using Multiple Lists variant (`→ engine/08-variations.md` §Multiple Lists).

## Failure modes

- **Adding every NPC** — clutters the random pool with noise. Only add what could plausibly act.
- **Skipping the 3-instance cap** — one element starts dominating every roll.
- **Forgetting to add a prominent ongoing Thread** — Random Events on subsequent Scenes can't invoke it.
- **Removing a Character because they exited the scene** — they may still recur. Remove only when they're truly done with the adventure.
- **Treating blank-line Choose as "this shouldn't have rolled"** — Choose is a feature: it's the moment to nudge or reroll consciously.
